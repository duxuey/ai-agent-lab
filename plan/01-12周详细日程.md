## 第一阶段：心智模型（W1–W2）

### W1 · LLM 是怎么生成文字的

**本周目标**：建立"概率文本生成 + 上下文决定输出"的直觉；能不查文档稳定调用 API 并控制输出格式。

| 天 | 理论（60min） | 实践（50min） | 产出 |
|---|---|---|---|
| D1 | token 与 BPE 分词；为何中文/代码更费 token；上下文窗口的成本含义 | 用 `tiktoken` 统计同一段中英文、代码、JSON 的 token 数并对比 | `token_cost.py` + 一张对照表 |
| D2 | Transformer 直觉：自注意力在算什么；残差与层堆叠；为什么"预测下一个词"能涌现能力 | 用 bbycroft.net/llm 观察一层层向量变化，记录 3 个反直觉点 | 笔记《attention 到底在做什么》 |
| D3 | 采样：temperature、top_p、top_k、stop、惩罚项；为什么同 prompt 结果不同 | 同一 prompt 跑 10 组参数，做输出差异对照表 | 参数对照表 + 结论 3 条 |
| D4 | Chat API：messages 角色分工、system prompt 的作用、流式输出、计费口径 | 写 CLI 聊天机器人：多轮历史、流式打印、`/clear`、token 计数 | `chat_cli/`（可运行） |
| D5 | 提示词结构：角色/任务/约束/示例/输出格式；指令冲突时模型如何取舍 | 同一任务写 5 版 prompt（含 1 版故意含糊），记录差异 | 5 版 prompt + 对比结论 |
| D6 | 结构化输出：JSON mode、function schema、Pydantic 校验与重试 | 做简历/发票信息抽取器：schema 定义 → 解析 → 校验 → 失败重试 | `extractor/`（含 10 条样本测试） |
| D7 | 复盘：本周卡片全过一遍，写周记 | 补欠账；把 chat_cli 推到 GitHub | 周复盘 + 首篇博客草稿 |

### W2 · 上下文工程与提示词工程

**本周目标**：从"会写 prompt"升级到"能设计上下文并度量效果"。这是 Agent 工程的核心能力。

| 天 | 理论（60min） | 实践（50min） | 产出 |
|---|---|---|---|
| D1 | 上下文窗口的分配；lost in the middle；信息顺序与冗余的代价 | 把同一份长文放开头/中间/结尾各问 5 题，统计正确率 | 位置敏感性小实验 |
| D2 | 提示词技术：CoT、任务分解、自洽投票、few-shot 示例选择 | 逻辑/数学题上对比「直接答 vs CoT vs 自洽 5 次投票」 | 三种策略准确率对比 |
| D3 | 提示词注入：直接注入、间接注入（来自检索/网页/文件）；为什么"加一句不要听用户的"没用 | 构造 10 条攻击样本，测试自己的 bot，记录哪些成功 | 攻击样本集 + 防御清单 |
| D4 | 评测入门：测试集、评分 rubric、批量跑分、通过率 | 为抽取器写 20 条测试用例 + 评分脚本，跑出基线分 | `eval/` + 基线报告 |
| D5 | 模板工程：变量、版本、复用；把 prompt 当代码管理 | 用 Jinja2 做模板库（3 个可复用模板），接入抽取器 | `prompts/` 模板库 |
| D6 | 工作流自动化：识别可自动化的重复任务；失败兜底设计 | 选自己一个真实重复任务做成脚本（周报汇总/邮件分类/会议纪要→行动项） | 一个每天能用的自动化脚本 |
| D7 | 复盘：本周哪个 prompt 技巧最有效？ | 补欠账；把 prompt 库写进笔记 | 周复盘 + 第二篇博客 |

## 第二阶段：知识供给（W3–W4）

### W3 · 嵌入与向量检索

**本周目标**：理解检索为什么有效、为什么失效；做出第一个带引用的 RAG。

| 天 | 理论（60min） | 实践（50min） | 产出 |
|---|---|---|---|
| D1 | 嵌入是什么：把语义映射到向量；cosine 与 dot 的区别；模型与维度选择 | 用 embedding 做语义搜索 demo（20 条句子，找最相似） | `embed_demo.py` |
| D2 | 分块策略：固定长度、递归、按结构、父子块；chunk size 与 overlap 的取舍 | 同一份文档 4 种切法，各抽 10 个问题比较命中 | 分块对比表 |
| D3 | 向量库：FAISS / Chroma / pgvector 的定位；索引、持久化、元数据过滤 | 索引 200 篇本地文档，实现 top-k + 元数据过滤 | `rag/index.py` |
| D4 | 检索评测：recall@k、MRR、nDCG；如何构造问答测试集 | 手工构造 50 条 QA，写脚本算 recall@5 与 MRR | `eval_retrieval.py` |
| D5 | 混合检索：BM25 与向量的互补；RRF 融合；何时必须混合 | 实现 BM25 + 向量 + RRF，对比纯向量召回 | 混合检索对比结论 |
| D6 | RAG 全链路：检索 → 拼上下文 → 生成 → 引用 | 做个人笔记问答 CLI，答案必须带来源片段 | `rag_cli/` 可运行 |
| D7 | 复盘：哪类问题检索失败最多？ | 补欠账；整理失败案例 10 条 | 周复盘 + 失败案例集 |

### W4 · RAG 的质量与生产化

**本周目标**：从"能答"到"答得准、敢拒答、可评测、能上线"。

| 天 | 理论（60min） | 实践（50min） | 产出 |
|---|---|---|---|
| D1 | 重排：cross-encoder 与 API rerank；为什么召回多、排序精 | 接入 rerank，对比加与不加的答案质量 | rerank 前后对比 |

| D3 | 引用与溯源：片段级引用怎么定位；无答案检测与拒答阈值 | 加「找不到就说不知道」策略，用 10 条无答案问题验证 | 拒答测试结果 |
