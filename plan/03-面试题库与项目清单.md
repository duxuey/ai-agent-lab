# 面试题库与项目清单

> 用法：每周五抽 5 题口述作答（不看答案），答不出的记进错题清单，W12 集中过一遍。
> 每题给「答题骨架」，不是标准答案——面试要的是结构清晰 + 有具体经验支撑。

---

## A. LLM 基础（10 题）

**A1. 一个 token 是什么？为什么中文通常比英文更费 token？**
骨架：BPE 子词单元 → 词表与合并规则决定切分 → 中文常用字词在词表中覆盖不同，多字节字符常被拆成多个 token → 影响上下文占用与计费。

**A2. 用一句话解释 Transformer 的 self-attention 在做什么，为什么它比 RNN 好训？**
骨架：每个位置按相关性加权聚合其他位置的信息 → 并行计算所有位置 → 长距离依赖路径短、梯度更稳。

**A3. 什么是上下文窗口？窗口变大就一定能解决"记不住"吗？**
骨架：一次前向能看到的 token 上限 → 变大有成本、延迟、"lost in the middle" 与注意力稀释问题 → 真正解法是检索、摘要、结构化状态。

**A4. temperature 和 top_p 分别控制什么？temperature=0 能保证复现吗？**
骨架：温度缩放 logits 的平坦度；top_p 是累积概率截断 → 0 不等于确定性：浮点非确定性、批处理、后端版本、并行归约。

**A5. 为什么模型会"幻觉"？工程上有哪些缓解手段？**
骨架：本质是最大化似然而非事实性；训练数据缺失/冲突、上下文缺失、指令要求"必须回答" → 缓解：检索 grounding、强制引用、拒答策略、结构化校验、自我一致性、外部工具核验。

**A6. 什么是"上下文工程"？和 prompt engineering 有何不同？**
骨架：从"写好一句话"到"设计模型每一步看到什么" → 包含检索内容、工具返回、历史压缩、指令层级、格式 → 是 Agent 系统的核心设计面。

**A7. 解释 CoT 为什么有效，以及它什么时候没用甚至有害。**
骨架：把隐式计算外显成中间 token，给模型更多计算步与中间状态 → 无效场景：简单任务、推理模型已内化、CoT 内容不忠实（说一套算一套）、增加延迟与成本。

**A8. 预训练、SFT、RLHF/DPO、RLVR 分别解决什么问题？**
骨架：预训练学语言与世界知识 → SFT 学"按指令回答"的格式与风格 → 偏好优化让输出更符合人类偏好 → 可验证奖励的 RL 提升推理正确率。

**A9. LoRA 的原理是什么？rank 选小了会怎样？**
骨架：冻结原权重，用低秩矩阵 A·B 近似增量 → 可训练参数大幅减少、显存友好、可插拔 → rank 过小欠拟合（学不到领域知识），过大接近全量微调且易过拟合。

**A10. 什么情况下应该微调，而不是用 RAG 或改 prompt？**
骨架：需要稳定格式/风格/领域术语、有大量高质量标注、推理成本要压低（小模型替代）→ 不该微调：知识频繁更新（用 RAG）、只需少量行为调整（用 prompt）、数据不足。

## B. RAG（10 题）

**B1. 画出你的 RAG 链路，并指出三个最可能出错的环节。**
骨架：解析 → 分块 → 嵌入 → 索引 → 检索（召回）→ 重排 → 上下文拼装 → 生成 → 引用 → 评测；脆弱点：解析丢结构、分块切断语义、召回不到/重排错、上下文超长、无答案硬答。

**B2. chunk size 怎么定？太大太小各有什么问题？**
骨架：按文档结构与问题粒度定（问答型偏小、总结型偏大）→ 太小丢上下文、召回碎片化；太大噪声多、挤占窗口、稀释相关信号 → 用评测集做消融，别凭感觉。

**B3. 为什么需要混合检索？RRF 做了什么？**
骨架：向量擅长语义、BM25 擅长的精确词/专名/编号 → 互补；RRF 用排名倒数求和融合，避免不同分数量纲不可比。

**B4. 如何衡量检索质量？recall@k 和 MRR 分别反映什么？**
骨架：recall@k = 前 k 里是否包含正确片段；MRR = 正确片段排名倒数的均值，反映"排得靠不靠前"；还要看延迟与索引成本。

**B5. 用户问的问题在知识库里没有答案，你的系统怎么处理？**
骨架：检索分数阈值 + 让模型显式判断"证据是否充分" → 输出"不知道 + 建议" → 用无答案集评测误答率；不能只靠 prompt 里写"不要编造"。

**B6. 如何做 RAG 的端到端评测？三个核心指标是什么？**
骨架：faithfulness（答案是否被上下文支持）、answer relevance（是否答到点上）、context precision/recall（检索质量）→ 用 LLM-as-judge + 人工抽样校准 → 建回归集防退化。

**B7. 多轮对话里，"他上一句说的那个方案"这种指代怎么处理？**
骨架：指代消解式 query 改写（结合历史生成独立 query）→ 也可以让检索吃"历史+当前"的拼接 → 风险是改写引入噪声，需要原文兜底。

**B8. 文档每天更新，索引怎么维护？**
骨架：增量索引 + 文档版本/哈希去重 → 删除与更新要同步（否则答旧内容）→ 全量重建的时机与成本 → 元数据加时间戳，检索时可按新鲜度加权。

**B9. 引用（citation）为什么难做对？你会怎么实现？**
骨架：模型生成的引用可能是编的 → 让模型输出片段 id 而非自由文本 → 服务端按 id 回填原文与链接 → 校验引用片段是否真的支持该句。

**B10. 表格、扫描件 PDF、图片型文档怎么进 RAG？**
骨架：优先结构化解析（表格转 markdown/CSV，保留表头）→ 扫描件需 OCR 或视觉模型 → 版式信息（标题层级）用于分块 → 对表格问答可考虑"文本检索 + 代码/表格查询"混合。

## C. Agent（12 题）

**C1. 什么是 AI Agent？它和"workflow + LLM"的本质区别？**
骨架：Agent 由模型自主决定下一步动作与工具，循环直到目标达成；workflow 的路径由人预先编排 → 区别在"谁决定控制流" → 代价是延迟、成本、不可预测性。

**C2. 什么任务不该用 Agent？**
骨架：步骤固定、对确定性/延迟/成本敏感、错误代价高、可枚举分支 → 用 workflow 更可靠；Agent 适合开放、步骤不可预知、可容错的任务。

**C3. 描述 ReAct 循环，以及解析失败时你会怎么处理。**
骨架：Thought → Action（工具+参数）→ Observation → 重复直至 Final Answer；失败处理：约束输出格式（JSON/函数调用）、解析失败回灌错误信息重试、步数/预算上限、降级到固定流程。

**C4. Agent 陷入死循环怎么办？**
骨架：步数与 token 预算硬上限、重复动作检测（相同工具+参数）、状态哈希去重、反思节点提示"换策略"、超时后返回部分结果并说明。

**C5. 工具（function）怎么设计才好用？**
骨架：名字与描述要说明"何时用/不用"、参数少而明确、返回结构化且含错误码、幂等、危险操作需确认、粒度适中（太细步数爆炸，太粗不可控）。

**C6. 多智能体一定比单 Agent 好吗？**
骨架：不一定。好处是上下文隔离、并行、职责清晰、易评测；坏处是通信损耗、错误放大、成本翻倍、调试困难 → 判断标准：任务能否并行拆分、子任务是否需要不同工具/提示。

**C7. 子 Agent 之间怎么传信息？为什么只回传摘要？**
骨架：结构化结果（JSON/固定字段）而非原始对话 → 摘要控制上下文膨胀与成本，也避免污染主 agent 的判断 → 关键字段不可丢，需要 schema 约束。

**C8. Agent 的记忆怎么设计？**
骨架：短期=对话窗口 + 摘要压缩；长期=向量库/结构化档案；工作记忆=任务状态（计划、已完成步骤）→ 写入策略（什么值得记）、检索策略、遗忘与冲突处理。

**C9. 规划（planning）在 Agent 里怎么做？Plan-and-Execute 的坑是什么？**
骨架：先分解成子任务再逐步执行，或 ReAct 边走边规划 → 坑：计划基于不完整信息、执行偏离后不重规划、计划粒度过细导致僵化 → 需要"重规划"触发器。

**C10. 如何控制 Agent 的成本和延迟？**
骨架：小模型做路由/分类、大模型做难决策；缓存（精确 + 语义）；并行工具调用；上下文裁剪与摘要；流式输出改善体感；限制最大步数。

**C11. MCP 是什么？它解决了什么问题？**
骨架：模型与外部工具/数据之间的标准协议（client-server，tools/resources/prompts）→ 解决 M×N 的集成碎片化，一次实现多处复用 → 注意权限与信任边界。

**C12. 怎么评测一个 Agent？终态对了就够吗？**
骨架：不够。要看轨迹（工具选择、参数正确性、步数、无效循环）+ 终态正确性 + 成本/延迟；建黄金集与回归集；非确定性要用多次采样统计通过率。

## D. 工程、评测与安全（8 题）

**D1. 提示词注入是什么？为什么"在 prompt 里写不要听用户的"没用？**
骨架：攻击者通过用户输入或检索内容植入指令，模型无法可靠区分"数据"与"指令" → 防御要在架构层：权限最小化、工具白名单、内容与指令分离、输出校验、人工确认高危操作。

**D2. 间接注入为什么更危险？**
骨架：恶意内容藏在网页/文档/邮件里，Agent 主动读取时被劫持 → 用户无感知 → 需要来源分级、对外部内容降权、禁止外部内容触发高危工具。

**D3. LLM-as-judge 有哪些偏差？怎么校准？**
骨架：位置偏差（偏好前一个）、长度偏差、自我偏好、提示敏感 → 随机交换顺序、多次采样、与人工标注算一致性（如 Cohen's kappa）、固定 rubric。

**D4. 线上 Agent 要监控哪些指标？**
骨架：成功率/拒答率、平均步数与工具调用次数、P95 延迟、单次成本、工具错误率、注入拦截数、用户反馈与转人工率。

**D5. 怎么保证 prompt 改动不引入退化？**
骨架：prompt 版本化 + 回归评测集 + 灰度发布 + 可回滚 → 把 prompt 当代码：diff、评审、CI 跑分。

**D6. 用户数据要进模型，隐私上要注意什么？**
骨架：最小化采集、PII 识别与脱敏、日志留存期限、供应商数据使用条款、传输与存储加密、可删除权。

**D7. 一个 Agent 服务上线，怎么做容量与失败设计？**
骨架：异步队列削峰、超时与重试（幂等）、限流与配额、熔断降级（回退到检索/模板回答）、多模型冗余。

**D8. 你如何做技术选型（框架/模型/向量库）？**
骨架：先定约束（成本、延迟、数据合规、团队熟悉度）→ 做最小验证（同一任务跑 2 个方案）→ 用数据决策（通过率/成本/延迟）→ 保留切换成本低的方案。

## E. 系统设计模板（45 分钟白板用）

以「企业知识库 Agent」为例，固定五步：

1. **澄清需求（5min）**：用户是谁、规模（文档数/日活）、是否多租户、延迟与合规要求、成功指标。
2. **整体架构（10min）**：接入层（鉴权/限流）→ 编排层（意图路由/Agent）→ 能力层（检索、工具、LLM 网关）→ 数据层（向量库、元数据、日志）→ 观测层。
3. **核心链路（10min）**：一次提问的完整时序：鉴权 → 改写 → 混合检索 → 重排 → 拼上下文 → 生成（带引用）→ 校验 → 返回；标出每一步的失败与降级。
4. **非功能（10min）**：权限（文档级 ACL 必须在检索层过滤，不能只在生成层）、成本（缓存/路由）、延迟（并行/流式）、评测与监控。
5. **权衡与演进（10min）**：为什么不直接微调、为什么用混合检索、单 Agent 还是多 Agent、下一步做什么。

## F. 六个项目与验收标准

每个项目都要有：可运行代码 + README + 一段"已知局限"。

| # | 项目 | 周次 | 验收标准（做到才算过） | 面试可讲点 |
|---|---|---|---|---|
| 1 | CLI 聊天机器人 + 信息抽取器 | W1 | 流式多轮、token 计数；抽取器在 10 条样本上 JSON 合法率 100%、字段准确 ≥ 8 条 | 上下文管理、结构化输出与校验重试 |
| 2 | 工作流自动化脚本 | W2 | 解决自己一个真实重复任务，连续用 3 天；附 20 条评测集与基线分 | 如何定义"好用"、评测驱动改进 |
| 3 | 个人知识库 RAG | W3–W4 | 50 条 QA 上 recall@5 ≥ 0.7；答案带可点来源；无答案问题拒答率 ≥ 0.8；有消融实验报告 | 检索失败分析、混合检索、拒答设计 |
| 4 | 工具型助手 + 自建 MCP server | W5 | 4 个以上工具、并行调用、危险操作需确认；MCP server 可被官方 client 调通 | 工具设计、协议、权限边界 |
| 5 | 手写 Agent 内核 + 多智能体调研助手 | W6–W7 | 不依赖框架跑通 ReAct；研究助手产出 2000 字带引用报告；对比单/多智能体的成本与质量数据 | 控制流归属、上下文隔离、取舍 |
| 6 | 带评测与监控的线上服务 | W8–W9 | 有黄金集 + tracing + 监控面板；红队 15 条攻击拦截率 ≥ 0.8；Docker 一键启动 | 评测体系、可观测性、安全加固 |

### Capstone 选题三条标准

1. **真实用户**：你或同事真的会用（自己每周的重复劳动最合适）。
2. **可演示**：3 分钟内能让外行看懂价值。
3. **可度量**：有 1–2 个数字能证明它有效（节省时间、准确率、通过率）。

可选方向：会议纪要 → 任务分派 Agent；个人/团队知识库问答；简历筛选与面试问题生成；日报周报自动汇总；竞品调研报告生成；客服工单分类与草稿回复。
