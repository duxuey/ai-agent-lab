# 每日打卡与复习系统

> 打卡不是记流水账，而是**用 5 分钟完成三件事**：确认今天学了、把知识变成可复习的卡片、给明天留一个明确入口。

---

## 1. 每日打卡（5 分钟，收尾时做）

### 1.1 填写打卡表

打开 `学习打卡表.xlsx` → 「每日打卡」页，填当天一行：

| 字段 | 填法 |
|---|---|
| 理论学习 / 动手实践 | 打 ✓ 或写分钟数；两个都没做就不算今天完成 |
| 复习卡（张） | 今天复习了几张到期卡片，一般 3–8 张 |
| 耗时 | 实际分钟数，用于校准计划（连续两周低于 90 分钟就要缩范围） |
| 自评 1–5 | 3 = 按计划完成；5 = 有额外产出；1–2 = 没跟上 |
| 笔记/卡点 | 一句话：今天最反直觉的点，或卡住的地方 |
| 明日一件事 | 只写一件，明天开工直接做 |

### 1.2 三句话日记（写在笔记里，不写进表格）

```
今天学会了：______
还没想通：______
明天先做：______
```

### 1.3 出复习卡（关键动作）

今天的理论部分，提炼 **1–3 张卡** 写进 `notes/cards/`，一张卡一个文件或一行：

```markdown
Q: 为什么 temperature=0 也不能保证完全可复现？
A: 浮点累加顺序、批处理、GPU 非确定性、模型版本与后端都可能变化；
   工程上要"结果稳定"应做输出校验与重试，而不是依赖 temperature=0。
```

好卡的标准：**答案能在一分钟内说完，且能用来回答问题**。不要抄定义，要写"为什么/什么时候用/会怎么错"。

---

## 2. 间隔重复规则（1-3-7-15-30）

每张新卡在创建后的第 **1、3、7、15、30 天** 各复习一次，共 5 次。

- 打卡表的「复习卡」页会自动算出 5 个复习日期（在 C 列填创建日期即可）。
- 每天打卡前，筛选出「今天到期」的卡，口头或默写回答，答不上来的标记重来（日期改为今天，重新走一轮）。
- 每天复习量控制在 **3–8 张、10 分钟以内**；超了就说明卡造得太多，砍掉低价值的。

**为什么是这组数字**：1 天抗遗忘、3 天固化、7 天形成周节奏、15 天跨过"以为自己会了"的错觉、30 天进入长期记忆。你只有 12 周，5 次足够覆盖到面试期。

---

## 3. 每周复盘（D7，30 分钟）

填「周复盘」页，四个问题固定不变：

1. **Keep**：这周哪个做法有效，下周继续？
2. **Problem**：最大的卡点是什么？是概念不懂、环境问题，还是时间不够？
3. **Try**：下周只改一件事，具体到动作。
4. **账**：本周打卡 x/7，欠下的哪天补，还是直接放弃？

复盘后做两件事：
- 把本周所有卡过一遍（不按到期日，全量扫），删掉 20% 价值最低的；
- 更新 `notes/进度.md`：本周产出的代码路径、跑通的命令、踩过的坑。

---

## 4. 断更与降级机制

| 情况 | 处理 |
|---|---|
| 漏 1 天 | 第二天照常，不补。当天只做复习 + 看 5 分钟日程 |
| 漏 2–3 天 | 启动「最小打卡」：每天 15 分钟，只复习 3 张卡 + 写 1 行，持续到恢复状态 |
| 漏 ≥4 天 | 计划整体顺延一周，不压缩内容；在周复盘里写清触发原因 |
| 连续两周自评 ≤2 | 说明每天 2 小时定高了，改为 1 小时版：只看理论 + 隔天写代码 |

节假与春节（2027 年 2 月初）可整周降级，**顺延比硬撑更可持续**。

---

## 5. 进度指标（每两周看一次）

| 指标 | 及格线 | 优秀线 |
|---|---|---|
| 打卡率 | ≥ 80% | ≥ 92% |
| 累计复习卡 | ≥ 60 张 | ≥ 100 张 |
| 完成项目 | 4 个 | 6 个 + capstone |
| 面试题自测 | 答出 60% | 答出 85% |
| 笔记篇数 | 12 篇 | 24 篇（每周 2 篇） |

指标只用来调整节奏，不用来责备自己。

---

## 6. 每日一句话提醒（可贴在桌前）

> 先复习 10 分钟，再学 60 分钟，再写 50 分钟代码，最后 5 分钟打卡。
> 今天不写代码，就等于今天没学。
