# day05 · 同一任务 5 版 prompt

日期：2026-11-27 ｜ 阶段：W1 D5

任务：从一份会议记录里提取待办事项。每版只加一个变量。

| 版本 | 加了什么 | 字符 | 关键表现 |
|---|---|---|---|
| V1 含糊 | 只说"整理一下" | 435 | 自己加三节结构、备注列、末尾说明段 |
| V2 只给任务 | "提取待办事项" | 437 | 4 条表格 + 一段啰嗦的时间推理 |
| V3 加角色 | "你是项目经理助理" | 427 | 与 V2 几乎一致 |
| V4 加约束 | 责任人/截止/缺失写未提及 | 190 | 最干净，信息一条没少 |
| V5 加格式 | +markdown 表格 + 原文依据 | 404 | 可核验，但暴露两个瑕疵 |

## 五条结论

1. **含糊的代价是"形态不可控"，不是"一定编造"。**
   同一条 prompt、temperature=0 跑了两次：一次多出"状态：跟进中"（编造），一次没有。
   事实对不对看你运气；形态稳不稳才决定能不能写进系统。**正确性 ≠ 稳定性。**
2. **角色在任务明确时几乎无效**（V2 ≈ V3，只多了三个字）。
   角色适合"有多种风格可选"的场景（写文案、当评审、扮对手），提取事实类任务是装饰。
3. **约束的收益是"少废话 + 允许说不知道"**：V4 从 435 字降到 190 字，信息量不减。
   `未提及` 这个约定的价值在于：把"不知道"变成一个合法输出，而不是逼模型猜。
4. **格式约束买的是"可验证 + 可解析"**：V5 的原文依据列让每条都能核对，
   且能直接被代码解析成结构化字段。这是 W4 引用、W8 评测的地基。
5. **但严格约束有副作用**（本次实测发现）：
   - **过度"未提及"**：第 3 行截止时间写"未提及"，但原文有"下周排期再定"，
     模糊但有价值的信息被抹掉。下游会把"下周再定"误判成"没人管"。
   - **拼接引用**：第 1 行的"逐字摘抄"实际把三个人连续发言拼成一条，没加省略号，
     读起来像一个人说的。**每段都逐字，拼起来就变了语意。**
